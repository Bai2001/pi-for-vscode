## 1. 项目概述

### 1.1 一句话定位

在 VSCode 侧边栏里为 pi coding agent 提供一个类 Claude Code / Codex 体验的原生聊天面板：pi 以 SDK 进程内方式运行，具备图片粘贴、工作区文件引用、多会话并行、编辑器感知、内置浏览器驱动等完整能力。

### 1.2 背景与动机

- pi 本身的 TUI 终端体验很完善，但在 VSCode 中缺少一个原生 GUI：图片粘贴（终端受限，Windows 上尤其差）、文件点选、diff 审阅等交互在 GUI 里体验远好于终端。
- 市场上已有三款同类插件（pi-code-gui、pi-vscode、Crust），各有取舍，但没有一款完全贴合个人工作流。
- 本项目为**个人自用**，不发布市场，因此可以大胆砍掉产品级负担（多运行时、包管理、交互卡片平台等），聚焦日常开发效率。

### 1.3 目标

1. 一个日常可用的 pi GUI：聊天、流式、思考、工具调用、diff 全部渲染到位。
2. 输入效率：图片（粘贴/拖拽/选择 + 自动压缩）、`@` 文件、`/` 命令、当前文件上下文自动附加。
3. 编辑器感知：pi 能看到/操作 VSCode 的选区、诊断、打开的文件，并通过桥接工具驱动 VSCode 内置浏览器完成"改代码 → 跑起来 → 截图验证"的闭环。
4. 会话体系：多标签并行、持久化、与终端 pi 会话互通。

### 1.4 非目标（明确不做，见第 7 章）

包管理视图、Rust Pi / RPC 后端、交互卡片渲染系统、完整 pi 配置管理 UI、发布到插件市场。

### 2.2 关键技术事实（决策依据）

| # | 事实 | 出处 |
|---|---|---|
| F1 | Claude Code VSCode 插件实为**编辑器标签页 Webview**，并不在 Copilot Chat 里 | anthropics/claude-code#15037 |

| F5 | `edit` 工具返回 `details.diff`，可直接渲染内联 diff | pi docs: sdk.md |
| F6 | 会话存储为 `~/.pi/agent/sessions` 下的 JSONL 树结构，终端与 GUI 天然互通 | pi docs: sessions.md |
| F7 | VSCode 1.109+ 内置集成浏览器（可登录、DevTools）；1.110+ 提供 **agent 用的 Browser Tools**（`openBrowserPage` / `screenshotPage` / `clickElement` / `runPlaywrightCode` 等 10 个） | code.visualstudio.com/docs/agents/run/browser-tools |
| F8 | 内置浏览器工具注册于 VSCode 语言模型工具服务，**稳定 API `vscode.lm.tools` / `vscode.lm.invokeTool` 可被任意扩展调用**（无需 MCP、无需 proposed API） | vscode-browser-bridge 插件实现佐证 |
| F9 | pi SDK 的 `ExtensionRunner.setUIContext(uiContext, mode)` 允许宿主自定义 pi 扩展的 UI 实现（对话框等） | pi SDK 源码 dist/core/extensions/runner.d.ts |
| F10 | Chat Participant 富渲染仅限 Markdown/按钮/文件树/进度，无法做自定义 diff 与交互元素 | VSCode Chat API 官方文档 |

### 2.3 pi SDK 能力清单（本项目依赖面）

- `createAgentSession()` / `createAgentSessionRuntime()`：会话创建与替换（new/switch/fork）
- `session.prompt(text, { images, streamingBehavior })`、`steer()`、`followUp()`、`abort()`
- 事件流：`message_update`（text/thinking/toolcall delta）、`tool_execution_start/update/end`、`queue_update`、`compaction_*`、`auto_retry_*` 等
- `ModelRuntime.getAvailable()`、`setModel()`、`setThinkingLevel()`
- `SessionManager.create/open/list/listAll` + 会话树（`getTree` / `fork` / `getEntries`）
- `DefaultResourceLoader`：发现扩展、技能、prompt 模板（供 `/` 补全与 ctx.ui 桥接）
- `defineTool()` / `customTools`：注册 VSCode 桥接工具
- `ExtensionRunner.setUIContext()`：接管 pi 扩展对话框

## 3. 技术决策记录

| # | 决策点 | 选择 | 被否方案 | 核心理由 |
|---|---|---|---|---|
| D1 | UI 形态 | 侧边栏 Webview 视图（Codex 模式） | Copilot Chat participant；编辑器标签页（Claude 模式） | participant 有图片 0 字节 bug（F3）+ 富 UI 受限（F10）；侧边栏不占编辑器空间 |
| D2 | pi 集成方式 | SDK 进程内（`@earendil-works/pi-coding-agent`） | `pi --mode rpc` 子进程 | 桥接工具直调 VSCode API（一行 vs 一套 IPC）；类型安全；无子进程生命周期管理 |
| D3 | 运行时支持 | 仅 TypeScript Pi | 双运行时（+ Rust Pi） | Rust Pi 无桥接工具能力；双后端复杂度翻倍，个人自用无收益 |
| D4 | 会话存储 | pi 默认 `~/.pi/agent/sessions` | 自定义目录 | 与终端 pi 会话互通（F6） |
| D5 | 浏览器能力 | 代理 VSCode 内置 Browser Tools（`vscode.lm.invokeTool`） | 自研 webview iframe 浏览器；MCP server | 零浏览器引擎实现成本，拿到真截图/点击/Playwright 全套（F7/F8） |
| D6 | pi 扩展 UI | 桥接 `ctx.ui` 对话框到 VSCode 原生弹窗 | 完整交互卡片系统 | 对话框是扩展兼容性必需；卡片系统是平台能力，无消费场景 |
| D7 | 设置体系 | VSCode 设置贡献 + 面板内轻量设置弹层 | 完整自建设置 UI | 全局配置走原生零成本；会话级高频项放面板内随手切换 |
| D8 | 图片压缩 | Webview 端 canvas 压缩 | 扩展宿主 sharp（原生依赖） | webview 内零依赖完成，扩展宿主无需打包原生模块 |

│  │ [待发送图片区] [上下文 chip]                    │  │
│  │ [📎][🖼️][🌐][⚙️]  输入框  [发送/转向▾][⏹]     │  │
│  └───────────────────────────────────────────────┘  │
│           ▲ postMessage (JSON-RPC 风格)              │
│           ▼                                          │
│  扩展宿主（Extension Host, Node.js）                 │
│  ├─ 会话管理器：多 AgentSession 池 + 事件路由        │
│  ├─ 桥接工具注册（编辑器组 / 浏览器组）              │
│  ├─ ctx.ui 对话框桥接                                │

└──────────────────────────────────────────────────────┘

**运行环境要求**

- VSCode ≥ 1.110（Browser Tools 依赖；1.109 引入集成浏览器）
- 设置 `workbench.browser.enableChatTools = true`（默认开，扩展启动时检测并提示）
- Node.js / npm（扩展宿主自带运行时）
- pi 无需单独安装 CLI（SDK 随扩展打包）；API key 沿用 pi 现有配置（`~/.pi/agent/auth.json` / 环境变量）

## 5. 功能需求

> 优先级说明：P0 = 第一批实现（核心可用）；P1 = 紧随其后（体验完整）；P2 = 后续迭代（本期需求内、实现靠后）。

### F01 聊天与消息流（P0）

**描述**：面板核心消息流，完整渲染 pi 会话的全部消息类型。

**详细行为**

1. 消息类型：
   - 用户消息：文本 + 附件（图片缩略图、`@` 引用 chip、上下文附加标记）
   - 助手消息：流式文本（Markdown）+ 思考块 + 工具调用块，按内容块顺序渲染
   - 工具结果：归属对应工具调用卡片
   - 系统事件：压缩摘要、自动重试、排队消息提示，以轻量横条呈现
2. 流式渲染：`message_update` 的 `text_delta` 增量追加；自动滚动到底部，用户上滚后暂停自动滚动（出现"回到底部"悬浮按钮）
3. 思考块：`thinking_delta` 流式填充；流式期间默认展开，完成后默认折叠，标题显示"思考 · Ns"；可手动展开/折叠
4. 工具调用卡片：
   - 头部：工具图标 + 名称 + 状态（运行中 spinner / 成功 ✓ / 失败 ✗）+ 耗时
   - 参数区：可折叠，JSON 格式化展示；`bash` 显示命令高亮
   - 结果区：可折叠，默认展示摘要（前 N 行）；超长结果（>50KB）截断 + "查看完整输出"
   - `bash` 工具：`tool_execution_update` 实时滚动输出，自动跟随
   - `edit` / `write` 工具：结果区渲染内联 diff（见 F10）
   - 浏览器工具：`screenshot` 类结果显示截图预览
5. Markdown 渲染：CommonMark + GFM 表格；代码块按语言语法高亮 + 语言标签 + 复制按钮；链接可点击（外链确认后系统浏览器打开）
6. 消息操作：用户/助手消息 hover 显示操作条（复制全文）

**边界与异常**

- 中止（abort）时：正在流式的消息标记"已中止"，运行中工具卡片标记终止状态
- LLM 错误：消息流内联错误条（红色），显示错误摘要 + 重试按钮
- 自动重试：`auto_retry_start` 显示"第 n/m 次重试，Ns 后"倒计时横条
- 长会话：消息列表虚拟滚动（1000+ 消息不卡顿）
- 流式渲染节流：按帧批量追加（rAF 或 16ms 合并），避免每个 delta 一次重渲

### F02 输入框与消息发送（P0）

**描述**：多行输入框，发送、转向（steering）、排队、中止。

**详细行为**

1. 多行自动增高 textarea；Enter 发送、Shift+Enter 换行
2. **中文输入法兼容**：IME composition 期间的 Enter 不触发发送（`compositionstart/end` 状态守护）——中文用户关键
3. agent 空闲时：发送按钮正常发送（`prompt`）
4. agent 运行中：发送按钮变为下拉菜单，三项对应 SDK 原生能力：
   - **转向**（steer）：当前回合工具调用完成后立即插入新指令（`steer()`）
   - **排队**（followUp）：当前任务全部完成后执行（`followUp()`）
   - **停止并发送**：`abort()` 后立即作为新 prompt 发送
5. 中止按钮（⏹）：agent 运行中常显，点击 `abort()`
6. 排队消息展示：`queue_update` 事件驱动，输入框上方显示待转向/待排队消息列表（可点击撤销未投递项）
7. 输入框内容、待发送图片在标签切换时保留（每标签独立草稿）

**边界与异常**

- 会话正在压缩（compaction）时的输入：允许排队
- 空消息 + 无图片：发送按钮禁用

### F03 图片输入与自动压缩（P0）

**描述**：三个入口汇入统一待发送区，发送前自动压缩。

**详细行为**

1. 三个入口：
   - 剪贴板粘贴：webview `paste` 事件，过滤 `image/*`
   - 拖拽：输入区 `dragover` / `drop`，接受图片文件
   - 文件选择器：工具栏 🖼️ 按钮 → `showOpenDialog`（过滤 png/jpg/jpeg/gif/webp，可多选）
2. 待发送区：输入框上方缩略图行（图片名、原始大小、压缩后大小、`×` 移除）
3. **自动压缩**（webview 端 canvas，默认开启）：
   - 触发条件：原图 > 1MB 或最长边 > 2048px（阈值可配置）
   - 策略：等比缩放至最长边上限 → JPEG 质量从 0.92 递降（下限 0.6）二分尝试至 ≤ 目标大小（默认 2MB）
   - 透明背景 PNG：压缩后转 JPEG 会丢失透明 → 保留 PNG 仅缩放；GIF 动图跳过压缩
4. 硬上限兜底：压缩后仍 > 5MB（Anthropic API 限制）则拒绝，标红提示
5. 发送：全部转 base64 走 `prompt(text, { images })`；历史消息里图片渲染缩略图，点击放大预览

**边界与异常**

- 粘贴混合内容（图片 + 文本）：图片进待发送区，文本进输入框
- 一次性粘贴大量图片（>10）：全部接收，横向滚动展示，发送前逐个可删

### F04 `@` 工作区文件引用（P0）

**描述**：输入 `@` 触发文件补全弹层，选中以 chip 插入，随消息发送路径引用。

**详细行为**

1. 触发：输入 `@` 字符（非代码块内），弹层出现在输入框上方
2. 数据源：`workspace.findFiles`（自动尊重 `files.exclude` 与 `.gitignore`）+ 当前打开的编辑器列表（优先排序）
3. 匹配：fzy 风格模糊评分，对完整相对路径打分排序
4. 展示：文件图标（按扩展名）+ 文件名 + 灰色目录前缀；最多 50 条 + "输入更多过滤"
5. 键盘：↑↓ 选择、Enter/Tab 确认、Esc 关闭；继续输入过滤词
6. 确认后：光标处插入**结构化 chip**（非纯文本），显示 `文件名`，hover 显示完整路径
7. 发送时：chip 转换为 prompt 中的引用文本块（仅路径，pi 自行决定是否 read）：

   ```
   @src/app.ts
   ```

8. chip 可用退格整体删除

**边界与异常**

- 无工作区（空文件夹窗口）：弹层提示"无工作区文件"
- 超大仓库：`findFiles` 限制条数（如 5000），仅对子集模糊匹配

### F05 `/` 命令补全（P1）

**描述**：输入 `/` 触发命令补全，覆盖 pi 全部可调用命令。

**详细行为**

1. 数据源（`DefaultResourceLoader` 读取）：
   - 扩展命令（extensions 注册的 `pi.registerCommand`）
   - prompt 模板（`~/.pi/agent/prompts/` + `.pi/prompts/`）
   - 技能（skills，命令名 `skill:name`）
2. 展示：命令名 + 描述 + 来源徽标（扩展/模板/技能/项目/全局）
3. 选中插入命令名 + 空格；命令带参数提示的（prompt 模板变量）在描述中说明
4. 发送时命令原样传给 `prompt()`，由 SDK 展开执行

**边界与异常**

- 与 `@` 补层的冲突：`/` 只在输入起始或空格后触发；`@`/`/` 弹层互斥

### F06 上下文附加：当前文件/选区（P1）

**描述**：开关开启时，每条消息自动附带活动编辑器的文件与选区信息。

**详细行为**

1. 输入框工具栏 📎 开关（默认**开**），状态按工作区持久化
2. 输入框上方实时 chip：`📎 src/app.ts:12-18`（有选区）或 `📎 src/app.ts`（无选区）；hover 预览将发送的内容；无可用编辑器时显示"无活动编辑器"灰 chip
3. 发送时拼接（置于用户输入之前）：

   ```
   [当前编辑器: src/app.ts]
   [选区 L12-L18]
   <选区文本>

   ----

   <用户输入>
   ```

4. **dirty buffer**：选区文本取自内存文档（`TextDocument.getText(range)`），包含未保存修改
5. **焦点回退**：焦点在 webview/终端时 `activeTextEditor` 为 undefined → 使用最近缓存的编辑器选区（缓存于扩展宿主，监听 `onDidChangeTextEditorSelection`）
6. 截断：选区 > 200 行（可配置）截断，chip 标注"已截断"

**边界与异常**

- 活动编辑器为 diff 视图 / 设置页 / 输出面板：跳过，按无编辑器处理
- 与 `@` 引用、图片共存，互不干扰

### F07 多会话并行（标签页）（P0）

**描述**：面板内浏览器风格标签栏，每个标签独立 pi 会话。

**详细行为**

1. 标签栏：顶部水平布局（可横向滚动），`+` 新建，标签 `×` 关闭（仅 hover 显示）
2. 每标签独立：`AgentSession` 实例、模型、思考级别、会话文件、输入草稿、待发送图片、排队消息
3. **后台标签事件不丢**：非活动标签的 SDK 事件继续被扩展宿主接收并更新该标签的消息状态树，切换回来即见最新
4. 标签标题：会话名（pi `set_session_name`，双击标签可重命名）→ 无名时取首条用户消息前 20 字 → 空会话显示"新会话"
5. 流式中的标签显示动态 spinner 角标
6. 关闭确认：该标签正在流式时弹确认；关闭不删除会话文件（可从二期会话浏览器找回）

**边界与异常**

- 同时最大标签数：不做硬限制，内存层面 AgentSession 轻量
- 标签切换时旧标签消息虚拟列表状态保留（滚动位置记忆）

### F08 会话持久化与恢复（P0）

**描述**：会话存 pi 默认目录；VSCode 重启后恢复标签页集合。

**详细行为**

1. 存储：`SessionManager.create(cwd)`，即 `~/.pi/agent/sessions/<项目目录>/…jsonl`，**与终端 pi 完全互通**（终端 `pi --continue` 可续 GUI 会话，反之亦然）
2. 标签集合持久化：每次标签增/删/切换时写 `workspaceState`：

   ```json
   { "tabs": [ { "sessionFile": "C:/…/2026-03-xx-xxx.jsonl", "active": true }, … ] }
   ```

   只存路径与顺序；会话名单一来源为 session JSONL
3. 恢复时机：扩展激活 + 面板首次可见时读取，逐个 `SessionManager.open()` 重建会话，从 JSONL 重放完整消息流（含历史工具调用与 diff）
4. 恢复后活动标签还原为关闭前的
5. 开关可关闭此行为（设置项，默认开）

**边界与异常**

| 情况 | 行为 |
|---|---|
| session 文件被删/移动 | 该标签显示"会话文件不存在"占位（可关闭/新建），不影响其他标签 |
| 上次全部关闭后重启 | 自动新建空白标签 |
| 恢复中异常（文件损坏行） | 跳过损坏条目，尽可能恢复（pi SessionManager 自身容错） |
| 多项目窗口 | workspaceState 按工作区隔离，各窗口恢复各自的标签集合 |

### F09 模型与思考级别管理（P0）

**描述**：每标签独立的模型与思考级别选择。

**详细行为**

1. 模型选择器（输入框工具栏模型名按钮 → 弹层）：
   - 数据：`ModelRuntime.getAvailable()`（已配置鉴权的模型）
   - 分组按 provider；显示模型名 + 上下文窗口；当前项高亮
2. 思考级别：`off / minimal / low / medium / high / xhigh / max`，仅显示当前模型支持的级别
3. 切换即调 `setModel()` / `setThinkingLevel()`，会话中途可切（下一条消息生效）
4. 会话恢复时模型从 session 文件还原；模型不可用时回退默认并提示
5. 新标签默认模型：设置项可配（默认取 pi settings 的默认模型）

**边界与异常**

- 无任何可用模型（未配 API key）：面板显示引导状态（指向 pi 的 quickstart / `pi` 终端登录流程）
- 模型切换失败（如 key 失效）：错误通知 + 保持原模型

### F10 内联 diff 展示（P1）

**描述**：pi `edit` / `write` 工具的文件变更渲染为行级 diff。

**详细行为**

1. 数据源：`edit` 工具结果 `details.patch`（标准 unified patch 文本，解析后行级渲染；`details.diff` 为已排版展示文本）；`write` 新文件渲染为全新增
2. 渲染：文件名头（含完整路径，点击可复制）+ 行号 + 新增行绿 / 删除行红（取 VSCode 主题 diff 颜色变量，自动适配主题）
3. 折叠：大段未变更上下文折叠为 `⋯ N unchanged ⋯`，展开保留 ±3 行上下文
4. 单个工具卡片多个文件变更：依次堆叠多个 diff 块
5. 只读展示（pi 工具自动执行，无批准流程；回滚能力见 F18）

**边界与异常**

- diff 太大（>2000 行变更）：默认折叠为摘要（N 文件 / +x −y），点击展开

### F11 桥接工具：编辑器感知（P0 精简集 → P2 全套）

**描述**：注册进 pi 的自定义工具，`execute` 直调 VSCode API，让 agent 感知/操作编辑器。

**P0 精简集（4 个）**

| 工具 | 入参 | 行为 |
|---|---|---|

| `vscode_get_diagnostics` | `file?`（可选，相对/绝对路径） | 该文件或全工作区诊断列表（severity/source/code/message/range），按严重度排序 |

| `vscode_get_active_editor` | - | 活动编辑器（文件/语言/dirty/选区行范围）+ 全部打开的编辑器列表 |

**P2 全套补充（对齐 pi-vscode 的 24 工具面）**

| 工具 | 行为 |
|---|---|
| `vscode_get_document_symbols` | 文件大纲符号（语言服务） |
| `vscode_get_definitions` / `type_definitions` / `implementations` / `declarations` | 指定位置的定义/类型定义/实现/声明位置 |
| `vscode_get_references` | 指定位置引用列表 |
| `vscode_get_hover` | hover 文档 / 推断类型 / 签名 |
| `vscode_get_workspace_symbols` | 全局符号搜索 |

**通用要求**

- 每个工具的 `description` 写清用法与适用时机（模型依赖描述决策）
- 路径参数统一支持工作区相对/绝对路径
- 工具组开关：编辑器组可整体禁用（设置 + 面板弹层）
- 结果超限截断（返回 `truncated: true` + 摘要），保护上下文

### F12 桥接工具：内置浏览器驱动（P1）

**描述**：代理 VSCode 内置 Browser Tools（`vscode.lm.invokeTool`），让 pi 获得完整浏览器视觉/交互闭环。

**工具集（10 个，命名 `vscode_browser_*`）**

| 桥接工具 | 代理的内置工具 | 能力 |
|---|---|---|
| `vscode_browser_open_page` | `openBrowserPage` | 打开 URL，返回 pageId（触发 VSCode 分享确认） |
| `vscode_browser_navigate` | `navigatePage` | 跳转 / reload / back / forward |
| `vscode_browser_read_page` | `readPage` | 页面可访问性/文本快照 |
| `vscode_browser_screenshot` | `screenshotPage` | **截图以图片返回给模型**（视觉验证核心） |
| `vscode_browser_click` | `clickElement` | 点击元素 |
| `vscode_browser_type` | `typeInPage` | 输入文本 |
| `vscode_browser_hover` | `hoverElement` | 悬停 |
| `vscode_browser_drag` | `dragElement` | 拖拽 |
| `vscode_browser_dialog` | `handleDialog` | 处理原生 JS 对话框 |
| `vscode_browser_playwright` | `runPlaywrightCode` | 执行任意 Playwright 代码（最强兜底） |

**实现要点**

1. 调用链：pi 工具 `execute` → `vscode.lm.invokeTool(内置工具, 参数)` → 结果回转（`LanguageModelToolResult` 的 image part → base64 图片内容；text part → 文本内容）
2. 参数 schema：运行时从 `vscode.lm.tools` 读取内置工具实际 schema 做参数适配（优先动态适配，退化硬编码镜像）
3. 确认对话框（VSCode 核心行为，非我们实现）：`open`（带 URL）/ `navigate`（跳 URL）/ `playwright` 每次弹确认；其余在已分享页面直接执行。文档化告知可用 `chat.tools.global.autoApprove` 提示用户可配置自动批准
4. **前置检查**：扩展启动时检测 VSCode ≥ 1.110 且 `workbench.browser.enableChatTools` 开启；不满足则不注册浏览器工具组，并在设置弹层提示原因
5. 典型工作流（写进工具描述）：改代码 → `bash` 起 dev server → `open_page` → `screenshot` 看效果 → `click/type` 走流程 → `read_page` 断言 → 修 bug → 复验

**边界与异常**

- 内置工具不存在/被企业策略禁用：桥接工具返回清晰错误信息（含原因），模型可向用户转述
- 截图超大：用户侧截图附加（F13）经 F03 webview 压缩管线；agent 工具结果截图不压缩（宿主无 canvas），内置浏览器截图为视口尺寸通常远低于模型硬限，超限返回结构化错误
- 未分享页面调用交互类工具：返回 VSCode 原始错误（提示用户分享标签或让 agent 自行 open）

### F13 浏览器截图附加：用户侧入口（P1）

**描述**：输入框工具栏 🌐 按钮，把当前集成浏览器页面截图直接加入待发送图片区——"指给 pi 看"。

**详细行为**

1. 点击 → 扩展宿主调 `screenshotPage` 对当前已打开（且已分享）的浏览器 tab 截图 → base64 回 webview → 进入 F03 待发送区（可预览/移除）
2. 多个浏览器 tab：弹出 QuickPick 让用户选 tab（显示各 tab 标题）
3. 无可用 tab：提示"先在集成浏览器中打开页面"

### F14 pi 扩展对话框桥接（`ctx.ui`）（P1）

**描述**：通过 `ExtensionRunner.setUIContext()` 接管 pi 扩展的 UI 调用，映射到 VSCode 原生控件，保证已装 pi 扩展的兼容性。

**映射表**

| pi 扩展调用 | 实现 |
|---|---|
| `ctx.ui.select(title, options, opts?)` | `showQuickPick`（支持 pi 的 `timeout` 参数：自实现倒计时，超时自动关闭返回 undefined） |
| `ctx.ui.confirm(title, message, opts?)` | `showWarningMessage` + 确认/取消按钮（timeout 同上，超时返回 false） |
| `ctx.ui.input(title, placeholder)` | `showInputBox`（timeout 同上） |
| `ctx.ui.editor(title, prefill)` | webview 模态编辑器（架构 Q3 决议直接实现）；面板不可见时降级 untitled 临时文档 + 顶部通知"编辑完成后点击确认" |
| `ctx.ui.notify(msg, level)` | info/warning/error → 对应 `show*Message` |
| `ctx.ui.setStatus(key, text)` / `setWidget` | P1 no-op（安全忽略）；P2 映射到面板状态条/消息流内嵌 widget |

**边界与异常**

- 对话框属于哪个标签会话：扩展宿主按触发来源的 AgentSession 关联活动面板上下文；多标签并发时路由到发起会话的标签（不可路由时弹在主窗口并注明来源）

## 6. 非功能需求

### NFR01 性能

| 项 | 要求 |
|---|---|
| 消息流 | 虚拟滚动；10k 消息会话流畅滚动 |
| 流式渲染 | delta 按帧合并（≥16ms 批量），不因逐字符重渲卡顿 |
| 大工具结果 | >50KB 截断展示；完整内容懒加载 |
| webview 通信 | 高频消息（delta）批量合并传输；结构化 clone 可序列化 |
| 启动 | 面板首开 ≤ 2s 出现输入框（会话恢复异步进行，逐标签就绪） |

### NFR02 错误处理与韧性

| 场景 | 策略 |
|---|---|
| SDK 加载失败 | 面板全屏错误态 + 重载按钮 + 错误详情 |
| 无可用模型/API key | 引导态（登录指引，链接 pi quickstart） |
| 会话恢复失败 | 标签级错误占位，不阻塞其他标签 |
| LLM 请求错误 | 消息流内联错误条 + 重试；自动重试事件可视化 |
| webview 崩溃/被回收 | **扩展宿主持有全部会话状态**（架构原则：webview 无状态可重建），webview 重载后从状态树重建 UI |
| 桥接工具异常 | 返回结构化错误给模型（含原因与建议），不崩溃会话 |
| 浏览器工具不可用 | 优雅降级（工具组不注册 + 设置弹层提示） |

### NFR03 安全

| 项 | 要求 |
|---|---|
| webview CSP | 严格 CSP；脚本 nonce；不启用 `enableCommandUris` |
| Markdown XSS | 渲染器 sanitize（安全配置），禁止原始 HTML（对齐 Crust 默认） |
| 外链 | 默认系统浏览器打开前确认 |
| 命令执行 | webview → 扩展宿主的消息为白名单命令路由（类型化协议），不透传任意命令 ID |
| 图片内存 | 超大 base64 不进持久状态树；压缩后进入 |
| 会话文件 | 只读写 pi 标准目录，不越权 |

### NFR04 兼容性与平台

| 项 | 要求 |
|---|---|
| VSCode 版本 | ≥ 1.110（`engines.vscode` 声明；1.110 以下安装时提示浏览器功能受限但可用） |
| 平台 | Windows 优先（用户主环境）；macOS/Linux 保持兼容（无原生依赖——图片压缩走 canvas 保障） |
| 中文输入法 | IME composition 全链路正确（发送、补全弹层触发词判定） |
| 主题 | 跟随 VSCode 主题（CSS 变量），支持高对比度 |
| 语言 | 界面文案中文；代码/标识符英文 |

### NFR05 可维护性

- TypeScript 全栈（扩展宿主 + webview），统一类型定义通信协议
- esbuild 打包；webview 独立 bundle
- 扩展宿主 / webview / SDK 集成 / 桥接工具 分层清晰（详细设计文档定义模块边界）
- 无原生依赖（node-gyp 类），保证跨平台安装零障碍

---

## 7. 明确不做（Out of Scope）

| 项 | 理由 |
|---|---|
| Rust Pi / RPC 子进程后端 | 无桥接能力、双后端复杂度翻倍；SDK 已满足（D3） |
| 包管理视图（pi package 的浏览/安装/卸载） | 个人用终端 `pi` 命令管理即可 |
| 交互卡片渲染系统（完整版） | 平台能力，无消费场景；对话框桥接已保证扩展兼容（D6） |
| 完整 pi 配置管理 UI（skills/上下文文件/prompt 模板开关矩阵） | 直接用 pi 自身机制管理，UI 不重复造 |
| 发布 VSCode Marketplace / Open VSX | 个人自用，vsix 本地安装 |
| 多窗口会话同步 | 单窗口工作流，多窗口各自独立 |
| 远程开发（Remote-SSH / Web）特殊优化 | 本地优先；远程场景不主动适配（能用即可，不做承诺） |

## 9. 开放问题（进入架构设计前确认）
