## 1. 开放问题决议（对应需求文档第 9 章）

| #   | 问题                  | 决议                                                                                               | 理由                                                                                       |
| --- | --------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Q1  | webview 前端框架      | **React 19 + TypeScript**，状态用 zustand                                                          | Markdown/虚拟列表/diff 组件生态最全；类型与宿主统一；个人维护成本最低                      |

| Q3  | `ctx.ui.editor` 实现  | **webview 模态编辑器**（textarea 弹窗）；面板不可见时降级 untitled 文档流                          | 我们自有 webview，模态是最自然的实现；降级路径保证可用性                                   |
| Q4  | 浏览器工具参数 schema | **注册时动态读取** `vscode.lm.tools` 实际 schema；读取失败/形状异常时回退内置硬编码镜像            | 跟随 VSCode 版本演进，硬编码兜底保证可用                                                   |
| Q5  | pi 会话行为设置写路径 | 面板弹层的自动压缩/自动重试经 **`SettingsManager` 写入 pi settings.json**（全局生效，UI 标注说明） | pi 行为配置归 pi 管，单一数据源；避免会话级覆盖造成"同设置两处真相"                        |
| Q6  | 会话浏览器 UI 形态    | P2 设计时定（倾向 webview 内弹层，与面板一体）                                                     | 不阻塞当前架构                                                                             |
| Q7  | 检查点快照存储        | P2 设计时定（倾向扩展 globalStorage 按会话组织 + LRU 清理）                                        | 不阻塞当前架构                                                                             |

## 2. 总体架构

三层结构，扩展宿主是唯一的权威状态源：

```
┌─────────────────────────────────────────────────────────┐
│  Webview（React 19 + zustand，侧边栏视图）               │
│  TabBar / MessageList(虚拟滚动) / Composer / 弹层        │
│  全标签消息镜像 + 输入草稿（本地图层状态）                │
└───────────────▲─────────────────────────────────────────┘
                │ postMessage（类型化协议：命令↑ / 推送↓）
┌───────────────┴─────────────────────────────────────────┐
│  扩展宿主（Extension Host，Node.js）                     │
│  ┌─────────────┐ ┌──────────────┐ ┌──────────────────┐  │
│  │ SessionPool │ │ StateStore   │ │ EventRouter      │  │
│  │ (AgentSession│ │ (每标签权威  │ │ (事件装配→批量   │  │
│  │  运行时池)   │ │  状态装配)   │ │  推送 webview)   │  │
│  └─────────────┘ └──────────────┘ └──────────────────┘  │
│  ┌─────────────┐ ┌──────────────┐ ┌──────────────────┐  │
│  │ BridgeTools │ │ ExtensionUi  │ │ Services         │  │
│  │ 编辑器/浏览器│ │ Bridge       │ │ 上下文跟踪/持久化│  │
│  │ (customTools)│ │ (ctx.ui 实现)│ │ /模型/文件搜索   │  │
│  └─────────────┘ └──────────────┘ └──────────────────┘  │
└───────────────▲─────────────────────────────────────────┘
                │ 直接函数调用（进程内）
┌───────────────┴─────────────────────────────────────────┐
│  pi SDK（@earendil-works/pi-coding-agent，打包进扩展）    │
│  AgentSession / AgentSessionRuntime / SessionManager     │
│  ModelRuntime / DefaultResourceLoader / ExtensionRunner  │
└─────────────────────────────────────────────────────────┘
```

**核心架构原则**

1. **宿主是唯一权威状态源**（NFR02）：所有会话消息、流式状态、队列状态装配在宿主的 `SessionStateStore`；webview 只是镜像 + 渲染层。webview 随时可被 VSCode 回收重建（重发全量快照即可恢复）。
2. **后台标签事件不丢**（F07）：EventRouter 对所有标签持续装配状态（无论是否活动），只是 webview 可见性不影响接收。
3. **webview 无副作用**：所有 VSCode API 调用（文件、QuickPick、诊断、浏览器工具）都发生在宿主；webview 仅通过协议发命令。
4. **协议类型单一来源**：`shared/protocol.ts` 双侧 import，编译期保证一致。

## 4. 状态模型

### 4.1 权威状态形状（宿主 SessionStateStore）

```typescript
// shared/protocol.ts（节选）

interface AppState {
  tabs: TabMeta[]; // 顺序 + activeTabId
}

interface TabMeta {
  tabId: string; // 扩展生成（非 pi sessionId）
  sessionFile?: string; // 恢复的会话文件；新会话首条消息后产生
  name?: string; // 会话名（源：session JSONL）；展示回退链（首条用户消息前 20 字 → "新会话"）由 webview 派生
  status: "loading" | "idle" | "streaming" | "error" | "invalid";
  error?: string; // status=error/invalid 时的用户可读信息
  model?: ModelRef; // provider + id + name + contextWindow
  thinkingLevel?: string;
  queue: { steering: QueuedMsg[]; followUp: QueuedMsg[] };
}

interface TabMessages {
  tabId: string;
  messages: UiMessage[];
}

type UiMessage =
  | {
      id: string;
      kind: "user";
      ts: number;
      text: string;
      imageIds?: string[]; // ImageStore 引用（懒加载）
      contextAttach?: { file: string; range?: [number, number]; truncated: boolean };
      mentions?: string[];
    } // @ 引用的路径列表
  | {
      id: string;
      kind: "assistant";
      ts: number;
      model: ModelRef;
      blocks: AssistantBlock[]; // 顺序：text/thinking/toolCall
      usage?: UsageSummary;
      stopReason?: string;
    }
  | {
      id: string;
      kind: "systemEvent";
      ts: number;
      event: "compaction" | "retry" | "error" | "notice";
      data: Record<string, unknown>;
    };

type AssistantBlock =
  | { type: "text"; text: string }
  | { type: "thinking"; text: string; durationMs?: number }
  | {
      type: "toolCall";
      toolCallId: string;
      name: string;
      args: unknown;
      status: "running" | "ok" | "error" | "aborted";
      result?: {
        summary: string;
        truncated: boolean;
        diff?: DiffData;
        imageId?: string;
        fullAvailable: boolean;
      };
      durationMs?: number;
    };
```

### 4.2 装配规则（SDK 事件 → 状态）

宿主按 SDK 文档的组装语义实现 `SessionStateStore.applyEvent`：

| SDK 事件                                            | 状态操作                                                                                   |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `message_start`（assistant）                        | 创建 assistant 消息 + 空 blocks                                                            |
| `message_update` 的 `text_delta` / `thinking_delta` | 按 `contentIndex` 追加/定位 block，追加文本                                                |
| `message_update` 的 `toolcall_end`                  | 插入 toolCall block（含完整 toolCall）                                                     |
| `message_end`                                       | 以事件内完整 message 为准**覆盖**装配结果（权威修正）                                      |
| `tool_execution_start/update/end`                   | 定位 toolCallId 的 block：状态 running → 更新 summary → ok/error + duration + diff/imageId |
| `queue_update`                                      | 更新 TabMeta.queue                                                                         |
| `compaction_*` / `auto_retry_*` / 错误              | 插入 systemEvent 消息 / 更新 TabMeta                                                       |
| `agent_start` / `agent_settled`                     | status streaming / idle                                                                    |

工具结果摘要策略：文本结果取前 30 行为 summary；`edit/write` 提取 `details.diff`；含图片内容（浏览器截图）时登记 ImageStore 返回 imageId；超 50KB 标记 `truncated` + `fullAvailable`。

### 4.3 推送模型（宿主 → webview）

- **全量快照 `state/snapshot`**：webview（重）加载时发送 `{ app: AppState, messages: TabMessages[]（全部标签）, images?: 立即可用的内联图片（用户消息压缩图） }`
- **增量补丁 `state/patch`**：宿主以 **16~32ms 合并窗口**批量推送：`{ patches: Array<{ tabId, upsert?: TabMeta; msgAppend?: UiMessage[]; msgUpdate?: { id, patch }… }> }`。补丁粒度：消息级追加 + 块级更新（`{ messageId, blockIndex, appendText? }`），前端 O(1) 应用
- 图片懒加载：`image/get { imageId }` 请求-响应，宿主从 ImageStore / session JSONL 返回 dataURL（带 LRU）

## 5. 通信协议

`shared/protocol.ts` 定义全部类型；两端各自封装（宿主 `protocolServer`、webview `protocolClient`，带自增 requestId 的请求-响应关联，Promise 化）。

### 5.2 推送（宿主 → webview）

| 推送               | 载荷                                              | 说明                                                                             |
| ------------------ | ------------------------------------------------- | -------------------------------------------------------------------------------- |
| `state/snapshot`   | 见 4.3                                            | webview（重）加载                                                                |

| `models/available` | `{ models }`                                      | 可用模型变化（登录/key 变更）                                                    |

| `notify`           | `{ level, message }`                              | 宿主侧通知（如浏览器工具不可用原因）                                             |

## 6. 核心数据流

### 6.1 发送消息（含图片与上下文）

```
Composer
  │ chat/send { text, images(dataURL), mentions, attachContext }
  ▼
PromptAssembler（宿主）
  │ 1. attachContext → ContextTracker 快照（文件/选区/dirty/截断）
  │ 2. mentions → 路径引用行（@path）
  │ 3. 上下文块 + 用户文本 拼接；图片 dataURL → ImageContent[]
  │ 4. 按会话状态选择：prompt() / steer() / followUp()
  ▼
SessionPool → AgentSession
  │ 事件流（message_update / tool_execution_* / queue_update …）
  ▼
SessionStateStore.applyEvent（权威装配）
  ▼
EventRouter ──(16~32ms 批量)──▶ state/patch ──▶ webview store ──▶ 渲染
```

**失败路径**：`chat/send` 前置失败（无模型/空输入）→ 同步响应 `accepted:false`，Composer 保留输入；接受后失败经事件流 → systemEvent('error') + 错误横幅 + 重试按钮。

### 6.2 会话恢复（启动/重载）

```
activate
  │ TabPersistence.read（workspaceState：tabs + sessionFile 列表）
  ▼
逐标签：SessionManager.open(file) → runtime 重建 → getEntries 重放装配
  │（损坏行跳过；文件缺失 → TabMeta.status='invalid'）
  ▼
webview 首次 resolveWebviewView → state/snapshot（全部标签）
```

**新会话的 sessionFile**：`SessionManager.create(cwd)`，首条消息后持久化产生；`TabPersistence` 监听标签变化写回。

### 6.3 桥接工具调用（浏览器示例）

```
pi agent 决策调用 vscode_browser_screenshot
  ▼ browserTools.ts（customTools 的 execute）
  │ 前置：工具组开关、lm.tools 可用性检查
  ▼ vscode.lm.invokeTool('screenshotPage', args)
  │ VSCode 核心：执行/确认对话框/分享检查
  ▼ LanguageModelToolResult
  │ image part → ImageStore 登记 imageId（不压缩，决策见 7.3）
  │ text part → 文本内容
  ▼ 返回 ToolResult → tool_execution_end → 常规事件装配链路
```

### 6.4 ctx.ui 对话框（pi 扩展 → VSCode/webview）

```
pi 扩展 await ctx.ui.select(...)
  ▼ ExtensionUiBridge（setUIContext 注入）
  │ select/confirm/input → vscode.window.showQuickPick / showInputBox / showWarningMessage
  │ editor → dialog/request → webview 模态 → dialog/response（面板不可见时降级 untitled 文档流）
  │ notify → show*Message；setStatus/setWidget → no-op；custom() → undefined
  │ timeout 参数：宿主 setTimeout 自动以默认值返回
  ▼ resolve pi 扩展的 Promise
```

## 7. 桥接工具实现要点

### 7.1 注册方式

`SessionPool` 创建会话时统一注入：

```typescript
createAgentSession({
  customTools: [
    ...editorTools(contextTracker), // 编辑器组（开关控制）
    ...browserTools(), // 浏览器组（前置检测通过才含）
  ],
  // tools: [...默认 + 桥接名]（按组开关过滤）
});
```

工具组开关闭 = 重建会话工具集或下个标签生效——**决定：即时生效**，调 `AgentSession.setActiveToolsByName()` 按组开关重算活动工具名集合，无需销毁会话。

### 7.2 编辑器组（P0 四件套）

均为薄封装：`vscode_get_selection` ← ContextTracker 缓存；`vscode_get_diagnostics` ← `languages.getDiagnostics`（格式化 + 按 severity 排序 + 上限 200 条）；`vscode_open_file` ← `workspace.openTextDocument` + `window.showTextDocument` + `revealRange`；`vscode_get_active_editor` ← `window.activeTextEditor` + `window.tabGroups`。

### 7.3 浏览器组（10 个代理）

- **命名映射**：`vscode_browser_open_page` ↔ 内置 `openBrowserPage`，其余一一对应（见需求 F12）
- **参数透传**：以动态读取的 schema 校验后透传给 `lm.invokeTool`
- **结果转换**：`LanguageModelToolTextPart → text`；`LanguageModelDataPart(image) → ImageContent`（模型直视图片）。**截图不压缩**：宿主无 canvas 且禁原生依赖，F03 压缩管线仅在 webview 端；内置浏览器截图为视口尺寸，通常远小于 5MB 模型硬限，超限则返回结构化错误让模型调整（用户侧 F13 截图附加走 webview 待发送区，天然经过 F03 管线）
- **不可用降级**：注册期检测（VSCode 版本 + `workbench.browser.enableChatTools` + `lm.tools` 中存在 browser 工具）失败则整组不注册，设置弹层展示原因；运行期 invoke 异常转结构化错误文本返回模型

## 8. webview 关键实现

### 8.1 渲染栈

| 关注点    | 方案                                                                                                                                           |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 虚拟滚动  | **virtua**（动态高度友好，chat 流式追加场景稳定）                                                                                              |
| Markdown  | **react-markdown + remark-gfm**，禁 raw HTML（NFR03）                                                                                          |
| 代码高亮  | **Shiki**（VSCode 同款，跟随主题；语言包懒加载，bundle 按需）                                                                                  |
| Diff 渲染 | 自研 `DiffView`：pi edit 结果 `details.patch` 为标准 unified patch 文本（`details.diff` 为已排版展示文本），解析 patch 行级渲染 +/- 着色与折叠 |
| 主题      | 全量使用 VSCode CSS 变量（`--vscode-*`），自动适配亮暗与高对比度                                                                               |
| 样式      | CSS Modules / 原生 CSS（不引 UI 库，体量小且贴合 VSCode 视觉）                                                                                 |

### 8.2 输入区（Composer）

- IME 守护：`compositionstart/end` 期间 Enter 不发送；补全弹层触发判定跳过 composition 内的 `@`/`/`
- 发送语义：空闲 → 发送（`chat/send`）；流式 → 下拉三选：steer → `chat/steer`、followUp → `chat/followUp`、stop&send → `chat/abort` + `chat/send` 组合
- 每 tab 独立草稿（`input` store 按 tabId 分桶），切标签无缝
- 待发送图片条：压缩前后大小展示、移除、点击预览

### 8.3 图片压缩管线（webview 端）

```
原图(File/Blob/dataURL)
  ▼ 需要压缩？（>1MB 或 最长边>maxDimension；GIF 跳过）
  ▼ canvas 等比缩放至 maxDimension 内
  ▼ toBlob('image/jpeg', quality) 二分递降（0.92→0.6，至 ≤targetSize）
  ▼ PNG 透明检测：含 alpha 且无背景 → 保留 PNG 仅缩放
  ▼ 仍 >hardLimit → 拒绝（标红提示）
```

配置实时读取宿主设置（快照携带 + `settings/set` 回执 + `settings/changed` 推送联动，覆盖外部修改 VSCode 设置的场景）。

### 8.4 状态镜像

zustand 三 store（`tabs` / `messages` / `input`）+ `ui`；`messages` 按 tabId 分桶应用 patch：

- `msgAppend`：push + 虚拟列表追加锚定
- 块级 `appendText`：直接改对应 block，流式期间仅该消息重渲（组件级 memo）
- `msgUpdate`：覆盖式合并（message_end 权威修正、工具状态变更）

## 9. 错误处理与韧性设计

| 场景              | 机制                                                                          |
| ----------------- | ----------------------------------------------------------------------------- |
| webview 回收/重载 | resolveWebviewView → 全量 snapshot 重建；开发期反复重开面板即回归验证         |
| SDK 加载失败      | activate try/catch → webview 全屏错误态 + 「重载窗口」按钮 + 错误详情         |
| 无可用模型        | snapshot 携带空 models → 面板引导态（pi quickstart 指引 + 打开终端按钮）      |
| 会话恢复失败      | TabMeta.status='invalid' + error 文案；标签占位可关闭；不影响其他标签         |
| prompt 前置拒绝   | chat/send 同步 `accepted:false`（输入保留 + 原因提示）                        |
| LLM/流中错误      | systemEvent('error') + 错误横幅 + 重试按钮（`chat/send` 重发原文）            |
| 桥接工具异常      | execute 内 try/catch → `isError: true` + 结构化错误文本（模型可读原因与建议） |
| postMessage 洪泛  | 推送端 16~32ms 合并窗口；patch 内同键幂等覆盖                                 |
| ImageStore 内存   | LRU（默认 64 项 / 128MB 上限）；dataURL 超限不进 patch，一律懒加载            |

## 10. 安全设计

| 项           | 实现                                                                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| webview CSP  | `default-src 'none'; img-src ${webview.cspSource} data:; style-src ${cspSource} 'unsafe-inline'; script-src 'nonce-xxx'`（Vite 产物 nonce 注入） |

| 会话文件读写 | 仅经 pi SessionManager 标准路径                                                                                                                  |
